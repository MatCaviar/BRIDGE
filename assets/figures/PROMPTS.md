# BRIDGE Figure Design Notes

These four figures adapt the visual language of Figures 2–5 in the Qwen UI Agent paper package: off-white academic canvases, bold black headings, lavender system panels, cyan process arrows, warm status accents, rounded cards, and soft material-style shadows. The BRIDGE content is independently modeled from this repository.

## Figure 2 — Overview

Show BRIDGE as a project-to-real-device capability bridge. Contrast heterogeneous inputs and a portable capability contract on the left, then tell one left-to-right trajectory: project grounding, capability modeling, MCP/device invocation, and traceable results.

## Figure 3 — Infrastructure

Use a four-quadrant infrastructure composition. Connect source evidence, capability authoring, host MCP publication, and the Android executor through a central BRIDGE spine. Emphasize that the same contract spans multiple projects and mechanism routes.

## Figure 4 — Real-device runtime

Use three tall panels plus a bottom refinement loop. Present registry-driven routing, the `cmd.json`/`result.json` ADB mailbox, the thin executor, evidence review, and the `verified`/`probe`/`broken` lifecycle without implying unsupported autonomous promotion.

## Figure 5 — Capability flywheel

Use a two-stage composition. Stage I bootstraps a contract from source/APK/PRD/device observations. Stage II forms a circular loop from project change through analysis, validation, registry/MCP publication, invocation, evidence review, and contract refinement.
